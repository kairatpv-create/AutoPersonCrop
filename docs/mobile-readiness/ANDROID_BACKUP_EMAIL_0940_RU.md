## Итоговое поведение

- В настройках резервирования две кнопки: «Сохранить в файл» и «Восстановить из файла». Строка «Архив» с флажком убрана. Сохранение автоматически создаёт ZIP с полным JSON: записи, настройки интерфейса и вложения. Импорт прежних JSON/ZIP и проверка обязательной структуры сохранены.
- После успешного сохранения можно отправить копию себе через выбранное почтовое или другое приложение. Используется обычное Android-окно «Поделиться» с ZIP-вложением и временным разрешением чтения. Получателя и отправку подтверждает пользователь в почтовом приложении. Это работает независимо от конкретного почтового провайдера; Органайзер не получает пароль или доступ к почтовому ящику.
- Для восстановления нужно открыть JSON/ZIP-вложение письма через Organizer Pro. Если почтовый клиент не предлагает такое открытие, вложение можно скачать и выбрать кнопкой «Восстановить из файла». Поддерживаются `content://` URI с MIME ZIP/JSON, без обращения к удалённым URL или чтения почтового ящика.
- Новая `BackupImportActivity` требует PIN, когда он включён, выполняет чтение с прежними лимитами/CRC/проверкой JSON и показывает количество заметок, проектов и финансовых записей. Записи заменяются только после отдельного подтверждения. Отказ и ошибка предварительной проверки не вызывают восстановление. Подтверждённый импорт использует существующие транзакции, журнал и страховочные копии. При блокировке фона требуется PIN; окно защищено `FLAG_SECURE`. При повторном открытии вложения обновляется предварительный просмотр. Учтены системные отступы и контраст значков строки состояния.
- Раздел «Аккаунт и синхронизация» и подключение автоматического обмена к главному экрану убраны. Старые токены, metadata владельца, локальные/конфликтные копии и серверные данные не удаляются. Сервер и Render не меняются. Информация о данных доступна отдельно в настройках.
- Пакет `kz.kairat.organizer` и SQLite `organizer.db`, схема 9, сохранены. Версия обновлена для установки поверх 0.9.38/0.9.39.

## Проверка на телефоне

Сначала сохранить резервную копию рабочих данных. Установить APK поверх прежнего приложения, без удаления. Для проверки e-mail использовать отдельный набор искусственных данных: сохранить файл, отправить его себе, открыть полученное вложение через Органайзер, проверить PIN/подтверждение/отмену, затем восстановление. Реальная доставка писем зависит от установленного почтового приложения; тесты CI не используют настоящие письма, аккаунты или данные пользователя. Системное окно выбора почтового приложения, доставка через конкретного провайдера и все варианты MIME почтовых клиентов требуют проверки на телефоне.

Проект iOS, TestFlight, публикация и серверное развёртывание в этот этап не входят.
