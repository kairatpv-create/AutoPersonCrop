# D04 — проверка копии до восстановления

Основа: `organizer-mobile-readiness-20261021`, коммит
`86a0fcc51d41ac0f53cad9463d751df27e2b03a9`.

`BackupManager.restore` сначала полностью проверяет входной объект через
`BackupValidation`, затем подготавливает записи и настройки, и только после
этого вызывает замену базы и восстановление файлов. Удалён допуск копии только
по наличию `notes`. Ошибки формата имеют понятное русское/английское сообщение.

Обязательны точный `format`, числовые `version`/`createdAt` и все восемь массивов
данных. Проверяются объекты записей, обязательные поля и типы известных полей
без преобразования строк в числа/логические значения. Целые числа проверяются
на диапазон, дробные — на конечность. Файловые схемы 3–6 требуют `settings` и
`attachments`; облачная схема 7 допускает их отсутствие. Сохраняются прежние
значения по умолчанию для исторических необязательных полей и неизвестные
добавочные поля облачных записей. Неподдерживаемые версии отклоняются.

Перед записью также проверяются структура вложений, Base64 и соответствие
числа байтов полю `size`. Проверка ничего не записывает. Полностью пустые массивы
в корректной оболочке допустимы; отсутствие массива ошибкой пустоты не считается.

## Проверено

235/235 целевых сценариев на искусственных данных: исходный пример D04,
повреждённый JSON, неверный формат/версия, отсутствие каждого раздела и
обязательного поля записи, неверные типы разделов/полей, числовые переполнения,
повреждённые вложения, неполный JSON внутри ZIP, восстановление JSON/ZIP,
настроек и бинарного вложения, исторические схемы 3–5, пустые файловые копии и
пустые/непустые облачные снимки 7. После каждого отказа сравниваются полный
экспорт записей/настроек и SHA-256 SQLite, файлов вложений и их индекса.

Негативный контроль: тот же набор на исходной основе завершается с ошибкой;
пример `{"notes":[]}` принимается исходным кодом. Повторный полный аудит не
выполнялся. Результаты исправленной версии: `evidence/d04-backup-validation.json`.

Команда запуска из корня репозитория:

```sh
python tools/audit/run_jvm_audit.py --source mobile/android \
  --jars /path/to/supplied-jars --output /path/to/temporary-results \
  --suite backup-validation
```

Исполняется настоящий Kotlin-код слоя данных с SQLite JDBC и адаптерами Android;
это хостовые тесты, а не проверка на телефоне. Сеть и реальные данные не
используются. Версии зависимостей описаны в `tools/audit/README.md`.
Атомарность при ошибках ввода-вывода и обработка дубликатов остаются отдельными
задачами; алгоритмы записи и синхронизации в D04 не перепроектировались.

Проверочная компиляция настроена существующим workflow на отдельной ветке D04:
один вызов `gradle --no-daemon --build-cache -p mobile/android assembleDebug`,
без выгрузки APK-артефакта. Версия, подпись и интерфейс приложения не изменены.
