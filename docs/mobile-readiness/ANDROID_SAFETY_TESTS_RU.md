# Изолированная проверка Android

Это следующий этап после JVM-проверок D04–D06/D14 и исправлений синхронизации. Локальная Work-среда не имеет Android SDK/эмулятора/KVM. Подготовлен `.github/workflows/organizer-sync-safety.yml` для одноразового Android 16/API 36 x86_64 эмулятора GitHub Actions.

## Что выполняется

1. Одна команда Gradle `assembleDebug assembleDebugAndroidTest`: существующее приложение и тестовый APK. Установочные APK не выгружаются в артефакты.
2. Установка только на эмулятор. Скрипт требует `ORGANIZER_SYNTHETIC_ONLY=1` и проверяет `ro.kernel.qemu=1`.
3. Тестовые ContextWrapper направляют SQLite, файлы, кэш, внутренние снимки и preferences в отдельные синтетические каталоги/имена. Нет настоящих email/password, записей или запросов к production.
4. Проверки неполного JSON, чужого формата, типов всех восьми коллекций и финансовой записи: записи, PIN, индекс и файлы сохраняются после отказа.
5. Корректные JSON/ZIP, полная пустая копия, cloud v7, реальный SQL rollback, проверенная страховочная копия.
6. Офлайн-правка, закрытие/открытие SQLite и повторный обмен с синтетическим транспортом. Выход/попытка другого аккаунта сохраняют записи. Дополнительный Android-тест моделирует восстановление SQLite/вложений/обычных preferences без noBackup state и отвергает новый subject с тем же email, сохраняя записи/файлы. Это модель копирования на реальных Android API, не запуск облачного Android Backup Transport.
7. Два отдельных запуска инструментации, между ними `adb force-stop`: проверка другого PID, сохранённых записей/вложений/PIN/общего снимка и ожидающей офлайн-заметки.
8. Отдельный процесс убивается через Android `Process.killProcess` после установки новых вложений, до COMMIT SQLite. Следующий процесс проверяет восстановление старых записей и точных байтов файлов. Убитый запуск ожидаемо не возвращает JUnit OK; восстановительный тест обязан подтвердить маркер, другой PID и прежние данные.
9. Тест ограниченно ожидает публикацию системного уведомления (до 5 секунд), поскольку первый запрос activeNotifications может ещё не возвращать новую запись. Реальное уведомление при включённом PIN не содержит личного заголовка/текста и full-screen intent.
10. Smoke-запуск MainActivity, наличие UI hierarchy и отсутствие AndroidRuntime FATAL после запуска.

## Артефакты и границы

Workflow сохраняет только синтетические отчёты/вывод инструментации/UI hierarchy и JSON серверных проверок на 14 дней. APK не публикуется. Итоги после выполнения CI добавляются в `evidence/sync-release-ci.json`.

Это реальные Android API/SQLite/filesystem на эмуляторе, но не телефон пользователя, не физическое отключение питания и не исчерпывающая визуальная проверка. Офлайн моделируется отказом изолированного транспорта, а не изменением радиосети телефона. Не тестировались Google speech provider, реальная камера/микрофон/календарь, два физических устройства или production-сервер. UI-автоматизация picker и всех размеров/тем пока не выполнена. Один эмулятор API 36 не заменяет проверки минимального API 26 и разных производителей.

Отдельный job исполняет реальные Express/bcrypt/JWT и PostgreSQL 16. Имя БД строго `organizer_synthetic_safety`, адрес localhost/127.0.0.1; другой URL отвергается. Проверяются конкурентные первые PUT, revision 409, валидация, пароль/подтверждение удаления, отозванные JWT, соседний аккаунт и конкурентные PUT/удаление. Production Render не участвует.
